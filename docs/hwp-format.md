# HWP 파싱 노트 — 흔히 틀리는 다섯 자리

한글 문서를 직접 파싱해 보려는 분을 위한 기록입니다. 여기 적은 곳을 틀리면
**결과가 그럴듯해 보이는데 틀립니다.** 그게 가장 위험합니다.

HWP 5.0에서 셋(셀 좌표·제어 문자 폭·서로게이트 쌍), HWPX에서 둘(셀 주소·표 안
문단 중복)입니다. 각 항목마다 자가 진단법을 같이 적었습니다.

## 파일 구조

HWP 5.0은 OLE 복합문서 안에 zlib으로 압축된 이진 레코드입니다.

- `FileHeader` 36번째 바이트 — bit0 압축 여부, bit1 암호 여부
- `BodyText/SectionN` — 본문
- 레코드 헤더 4바이트 — 태그 10bit, 레벨 10bit, 크기 12bit.
  크기가 `0xFFF`면 뒤 4바이트가 실제 크기입니다

주요 태그입니다.

| 값 | 이름 | 내용 |
|---|---|---|
| 66 | `PARA_HEADER` | 문단 시작 |
| 67 | `PARA_TEXT` | 문단 글자 (UTF-16LE) |
| 71 | `CTRL_HEADER` | 개체 제어. 앞 4바이트가 뒤집힌 ASCII ID (`tbl `, `%unk` …) |
| 72 | `LIST_HEADER` | 표의 셀 하나. **표 레코드와 같은 레벨**로 나열됩니다 |
| 77 | `TABLE` | 표. payload 오프셋 4에 행 수, 6에 열 수 |
| 93 | `MEMO_LIST` | 메모 본문이 이 뒤에 붙습니다 |

## 함정 1 — 셀 좌표는 오프셋 8부터

`LIST_HEADER`의 앞부분은 리스트 공통 헤더(문단 수 2바이트 + 속성 4바이트 + 예약
2바이트)이고, **셀 속성은 오프셋 8부터** 시작합니다.

```
offset  8 : 열 주소 (col)
offset 10 : 행 주소 (row)
offset 12 : 열 병합 수 (colspan)
offset 14 : 행 병합 수 (rowspan)
```

오프셋 0부터 읽는 구현이 돌아다닙니다. 그렇게 하면 모든 셀이 `row=0, col=1`로
뭉개지고 병합 값이 `1280`, `32` 같은 쓰레기가 됩니다.

**증상을 알아채기 어렵습니다.** 셀 텍스트와 읽기 순서는 멀쩡하기 때문에, 단순한
표는 정상으로 보입니다. 2단 헤더가 있는 표에서만 열이 밀립니다. 그리고 그런 표가
바로 금액이 들어가는 표입니다.

자가 진단: **모든 셀의 row가 0이면 이 버그입니다.**

제대로 읽으면 이렇게 나옵니다.

```
r0 c0 span1x7   (단위: 원)
r1 c0 span2x1   품목
r1 c1 span2x1   규격
r1 c3 span1x2   단가
r1 c5 span1x2   금액
r2 c3 span1x1   정가
r2 c4 span1x1   할인가
```

## 함정 2 — 제어 문자 폭

`PARA_TEXT`에는 표·그림·필드 자리를 나타내는 제어 문자가 섞여 있고, 종류마다
차지하는 폭이 다릅니다.

- `0, 10, 13` → **1워드**(2바이트)
- 나머지 `1~23` → **8워드**(16바이트)

4~9번(필드 시작·끝 등)을 1워드로 처리하면 뒤따르는 이진 데이터가 글자로 새어
나옵니다. 이런 값이 보이면 이 버그입니다.

```
12,600浵ࡦ
```

숫자 뒤에 한자나 옛한글 비슷한 글자가 붙어 있는지로 알아챌 수 있습니다.

## 함정 3 — 서로게이트 쌍

코드 유닛을 하나씩 `chr()`로 바꾸면 BMP 밖 문자에서 `surrogates not allowed`
오류가 납니다. 연속 구간을 모아 `utf-16-le`로 한 번에 디코딩해야 합니다.

```python
run = bytearray()
...
run += payload[i * 2:i * 2 + 2]
...
out.append(run.decode("utf-16-le", "replace"))
```

## 메모(주석) 읽기

메모는 두 곳에 나뉘어 있습니다.

1. **자리 표시** — 본문 안에 `CTRL_HEADER`(71)로 들어갑니다. 제어 ID는 `%unk`이고
   payload에 `MEMO/65535/1/280877155/.../user/\;;` 같은 참조가 들어 있습니다
2. **본문** — 섹션 스트림 끝의 `MEMO_LIST`(93) 뒤에 문단으로 붙습니다

그래서 본문만 훑으면 메모가 통째로 사라집니다. 93 태그를 따로 처리해야 합니다.
hwp-reader는 자리 표시가 있던 셀에 `⟨메모⟩` 마커를 남겨 두 곳을 이어 줍니다.

## HWPX는 쉽지만, 쉬워 보여서 틀립니다

HWPX는 ZIP 안에 OWPML(XML)입니다. 표준 라이브러리만으로 읽힙니다.

- 본문: `Contents/sectionN.xml`
- 문단 `<hp:p>`, 글자 `<hp:t>`
- 표 `<hp:tbl>` → `<hp:tr>` → `<hp:tc>`

행 경계가 태그로 나뉘어 있어 쉬워 보이는데, 여기서 두 가지를 놓칩니다.

### 함정 4 — `<hp:tc>` 순서로 열을 정하면 안 됩니다

셀에는 주소와 병합 수가 따로 붙어 있습니다.

```xml
<hp:tc>
  <hp:cellAddr colAddr="3" rowAddr="2"/>
  <hp:cellSpan colSpan="1" rowSpan="1"/>
```

`<hp:tr>` 안에 나온 순서대로 0번 열부터 채우면, 위쪽 행에서 내려온 병합(rowSpan)이
차지한 자리를 무시하게 됩니다. HWP 5.0의 함정 1과 증상이 똑같습니다.

```
품목 | 규격 | 수량 | 단가        | 금액                     ← 2단 헤더
정가 | 할인가 | 공급가 | 부가세                             ← 0번 열부터 채워짐 (틀림)
     |        |        | 정가 | 할인가 | 공급가 | 부가세    ← 3번 열부터 (맞음)
```

자가 진단: **2단 헤더 표에서 아래 단이 왼쪽 끝에 붙어 있으면 이 버그입니다.**

`cellAddr`을 생략하는 생성기도 있으므로, 없을 때는 이미 놓인 셀의 병합 범위를
피해 커서를 밀며 자리를 잡아야 합니다.

### 함정 5 — 표 안 문단이 본문으로 한 번 더 나옵니다

셀 내용은 `<hp:tc>` 밑에 다시 `<hp:p>`로 들어 있습니다. 그래서 XML을 평평하게
훑으면서 `<hp:p>`를 전부 본문으로 담으면, **같은 표가 표로 한 번, 본문으로 한 번**
나옵니다. 표가 문서의 대부분인 한국 서식에서는 분량이 두 배로 부풀고, LLM에 넣으면
같은 숫자를 두 번 읽습니다.

"표를 품은 문단은 건너뛴다"로는 안 잡힙니다. 건너뛸 대상은 표를 품은 바깥 문단이
아니라 **표 안에 들어 있는 문단**이기 때문입니다. 표를 만나면 그 아래로 내려가지
않는 방식으로 훑어야 합니다.

자가 진단: **본문 텍스트에 표의 셀 값이 그대로 다시 보이면 이 버그입니다.**
