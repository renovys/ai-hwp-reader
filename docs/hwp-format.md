# HWP 파싱 노트 — AI에게 “그럴듯하게 틀린 문서”를 주지 않기 위한 자리들

AI HWP Reader가 가장 경계하는 실패는 예외가 아니라 **결과가 멀쩡해 보이는데 실제 문서와 다른 것**입니다. AI는 빠진 숫자나 밀린 열도 자연스럽게 해석할 수 있으므로, 파서 단계에서 구조를 최대한 보존하고 이상한 입력은 조용히 통과시키지 않습니다.

이 문서는 실제 회귀 시험으로 고정한 HWP/HWPX 파싱 함정을 정리합니다.

## HWP 5.0 파일 구조

HWP 5.0은 OLE Compound File Binary 안에 레코드 스트림을 담습니다. 일반 문서는 `BodyText/SectionN`에 본문이 있고 `FileHeader`의 속성에 따라 raw DEFLATE로 압축됩니다.

`FileHeader`는 `HWP Document File` 시그니처로 시작합니다. OLE 컨테이너에 `FileHeader`라는 이름의 스트림이 있다는 이유만으로 HWP라고 판단하면 다른 OLE 문서를 오인할 수 있으므로 실제 시그니처도 확인합니다.

주요 태그:

| 값 | 이름 | 내용 |
|---|---|---|
| 66 | `PARA_HEADER` | 문단 시작 |
| 67 | `PARA_TEXT` | UTF-16LE 문단 글자 |
| 71 | `CTRL_HEADER` | 표·메모 등 개체 제어 |
| 72 | `LIST_HEADER` | 표 셀 정보 |
| 77 | `TABLE` | 표 크기 정보 |
| 93 | `MEMO_LIST` | 메모 본문 |

레코드 헤더는 4바이트이며 태그 10bit, 레벨 10bit, 크기 12bit입니다. 크기가 `0xFFF`면 다음 4바이트가 실제 payload 크기입니다. payload가 섹션 끝을 넘어가면 손상된 문서로 처리해야 합니다.

## 함정 1 — 셀 좌표는 LIST_HEADER 오프셋 8부터

셀 속성은 다음 위치에서 시작합니다.

```text
offset  8 : col
offset 10 : row
offset 12 : colspan
offset 14 : rowspan
```

오프셋 0부터 읽으면 단순 표는 얼핏 정상처럼 보여도 2단 헤더에서 열이 밀립니다. 금액표처럼 병합이 많은 문서에서는 치명적입니다.

`LIST_HEADER`가 셀 좌표를 담기에 너무 짧은 경우도 그냥 건너뛰지 않습니다. 일부 셀이 사라진 표를 정상 결과로 돌려주는 것보다 오류를 내는 편이 안전합니다.

## 함정 2 — PARA_TEXT 제어문자의 폭이 다르다

`PARA_TEXT`에는 글자와 개체 제어가 섞여 있습니다.

- `0`, `10`, `13` → 1워드
- `1~23` 중 위 세 값을 제외한 제어 → 8워드

8워드 제어를 1워드로 건너뛰면 뒤의 이진 데이터가 글자로 새어 나옵니다. 실제 글자 스트림에 남는 `U+001F` 같은 C0 문자도 최종 출력에서는 공백으로 정리합니다.

## 함정 3 — UTF-16 서로게이트 쌍

코드 유닛을 하나씩 `chr()`로 바꾸면 BMP 밖 문자가 깨질 수 있습니다. 일반 글자 구간을 바이트로 모은 뒤 `utf-16-le`로 한 번에 디코딩합니다.

```python
run += payload[i * 2:i * 2 + 2]
text = run.decode("utf-16-le", "replace")
```

## 함정 4 — 섹션 이름을 문자열로 정렬하면 문서 순서가 틀어진다

`Section0`, `Section1`, `Section2`, … `Section10`을 단순 `sorted()` 하면 `Section10`이 `Section2`보다 앞에 옵니다. HWP와 HWPX 모두 끝의 숫자를 정수로 읽어 정렬합니다.

```text
잘못: Section0, Section1, Section10, Section2
정상: Section0, Section1, Section2, Section10
```

## 함정 5 — 손상된 크기값을 믿고 거대한 격자를 만들면 안 된다

HWP의 `TABLE` 행·열 수나 HWPX의 `rowCnt`·`colCnt`는 메모리 할당으로 이어집니다. 손상된 값이 들어오면 작은 파일 하나가 비정상적으로 큰 2차원 리스트를 만들 수 있습니다.

AI HWP Reader는 표 격자 크기를 메모리 할당 전에 검증하고 비정상적인 경우 명시적으로 실패합니다. 이 제한은 문서가 부분 성공한 것처럼 보이게 하지 않기 위한 방어입니다.

## HWP 메모(주석)

HWP 메모는 자리 표시와 본문이 나뉩니다. 본문의 `%unk` 제어가 메모 위치를 가리키고, 실제 메모 글자는 섹션 뒤쪽의 `MEMO_LIST` 이후 문단에 들어갑니다.

AI HWP Reader는 메모가 달린 셀에 `⟨메모⟩`를 남기고, 실제 본문은 `[메모]` 블록으로 출력합니다.

## HWPX는 XML이지만 구조를 평평하게 읽으면 안 된다

HWPX는 ZIP 안의 OWPML XML입니다.

- 본문: `Contents/sectionN.xml`
- 문단: `<hp:p>`
- 글자: `<hp:t>`
- 표: `<hp:tbl>` → `<hp:tr>` → `<hp:tc>`

### 함정 6 — `<hp:tc>`가 나온 순서가 열 위치가 아니다

병합 표에서는 위 행의 `rowSpan`이 아래 행의 칸을 이미 차지합니다. `<hp:tc>`를 보이는 순서대로 0번 열부터 채우면 열이 왼쪽으로 밀립니다.

가능하면 `cellAddr`의 `rowAddr`·`colAddr`을 사용하고, 주소가 생략된 문서에서는 이미 놓인 셀의 병합 범위를 피해 커서를 이동합니다. 음수 주소처럼 구조상 성립할 수 없는 값은 조용히 보정하지 않습니다.

### 함정 7 — 표 안 문단을 본문으로 다시 읽기 쉽다

셀 안의 텍스트도 `<hp:p>`로 표현됩니다. XML 전체의 `<hp:p>`를 평평하게 순회하면 표가 표 블록으로 한 번, 일반 본문으로 한 번 더 나옵니다. 표를 만나면 그 자식 문단을 일반 본문 순회에서 제외해야 합니다.

### 함정 8 — 표 안의 표는 쉽게 통째로 사라진다

HWPX 실무 문서에는 셀 안에 또 다른 `<hp:tbl>`이 들어가는 경우가 있습니다. 셀 텍스트 함수가 중첩 표를 단순히 건너뛰면 출자자 구성, 투자전략 같은 핵심 하위 표가 부모 셀에서 빈 값으로 사라질 수 있습니다.

AI HWP Reader는 중첩 표를 두 형태로 보존합니다.

1. 부모 셀 `text`에 `[중첩표]` 표기로 사람이 읽을 수 있는 내용을 넣습니다.
2. 해당 셀의 `nested_tables`에 원래 격자 구조를 재귀적으로 유지합니다.

예:

```text
[중첩표] 구분 | 금액 | 비율 / GP | 3 | 1.2% / LP | 247 | 98.8%
```

JSON/Python API에서는 같은 내용이 다시 `grid`와 `cells` 구조로 제공됩니다.

### 함정 9 — 문단 내부 메모 처리에서 부모를 다시 순회하면 중복된다

메모가 문단 중간에 들어간 경우 메모를 처리하기 위해 부모 노드를 다시 순회하면 메모 앞뒤 텍스트나 형제 노드를 두 번 읽을 수 있습니다. 메모 노드 자체만 별도 처리하고 텍스트 버퍼를 끊어 문서 순서를 보존합니다.

```text
본문 앞
[메모] 검토 내용
본문 뒤
```

### 함정 10 — 깨진 XML에서 어느 섹션이 실패했는지 알아야 한다

대형 HWPX는 여러 `sectionN.xml`로 나뉩니다. XML 파싱 오류를 그대로 올리면 사용자가 어느 섹션이 문제인지 찾기 어렵습니다. 오류 메시지에 파일 경로와 실제 `Contents/sectionN.xml` 이름을 포함합니다.

섹션 확장자의 대소문자가 다른 비표준 문서도 읽되, 섹션 번호는 항상 숫자 기준으로 정렬합니다.

## Markdown 출력도 구조의 일부다

셀 안에 실제 `|` 문자가 있으면 그대로 이어 붙인 Markdown은 열 하나를 추가한 것으로 해석됩니다. 셀 값의 `|`와 백슬래시는 이스케이프해야 표의 열 수가 유지됩니다.

중첩 표의 인라인 표기 안에 들어 있는 `|`도 최종 Markdown 렌더링 단계에서 동일하게 이스케이프됩니다.

## 자가 검증 원칙

- 2단 이상 병합 헤더로 열 위치를 확인합니다.
- 본문과 표가 중복되지 않는지 확인합니다.
- 표 안의 표가 누락되지 않는지 확인합니다.
- 메모가 본문과 분리되고 위치 정보가 남는지 확인합니다.
- 다중 섹션을 숫자 순서대로 읽는지 확인합니다.
- 출력에 C0 제어문자나 `�`가 남는지 확인합니다.
- 손상된 레코드·셀 주소·XML·표 크기를 부분 성공으로 처리하지 않는지 확인합니다.
- `skill/hwp_reader_single.py`와 `SKILL.md`는 직접 고치지 않고 `tools/build_single.py`로 생성합니다.
